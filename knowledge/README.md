# 직원 사전지식 (knowledge/)

직원이 짧은 지시도 알아듣도록, 분야별 **최신 기준**을 모아 둔 곳이다.
브랜드 규칙(`brand/RIAN.md`)·가게 사실(`brand/facts.md`)과 겹치면 **brand 파일이 이긴다.**

| 파일 | 내용 | 읽는 직원 |
|---|---|---|
| `request-defaults.md` | 짧은 지시를 풀어 읽는 법(기본값표) | 본부장·팀장 (모두 읽어도 됨) |
| `ad-disclosure.md` | 광고·협찬 표시 법 기준(공정위) | 모두 |
| `naver.md` | 네이버 블로그·검색·브랜드커넥트 | 네이버팀, 본부장 |
| `instagram.md` | 인스타그램 게시물·릴스·해시태그 | 인스타팀, 디자인팀, 본부장 |
| `threads.md` | 스레드 글자 수·태그·링크 | 스레드팀, 본부장 |
| `design-specs.md` | 채널별 그림 크기 | 디자인팀, 팀장들 |

## 항목 표기 규칙
모든 항목 끝에 `[근거 등급 · 출처 · 확인일]`을 단다.
- **공식** — 기관·플랫폼 원문(공정위·법령정보센터·Meta 개발자 문서·인스타 도움말)을 확인
- **공식(요약)** — 공식 페이지를 검색 요약으로 확인(원문 전체를 열지는 못함)
- **보도** — 언론 기사로만 확인. 경향으로만 쓰고, 글에 숫자로 단정하지 않는다
- **미확인** — 확인 못 함. 글·시안의 근거로 쓰지 않는다

직원이 지킬 것:
- 결과물에 넣는 사실은 **공식·공식(요약)** 만. 보도·미확인 항목은 판단 참고만 한다.
- 파일 맨 위 `최종 확인:` 날짜가 **30일이 지났으면** 결과 파일 맨 위에 "사전지식 오래됨: <파일>"을 적는다. 갱신은 `/knowledge-refresh`.
- 작업 중 사전지식과 다른 사실을 공식 자료에서 보면, 고치지 말고 결과 파일에 "사전지식 갱신 필요: …(출처)"로 적는다. 갱신은 비서가 `knowledge-refresh`로 한다.

자동 확인: `node tools/knowledge-check.mjs` (오래된 파일·근거 등급 빠진 줄을 알려 준다)
